# Security Log Analyzer

A beginner-friendly cybersecurity and data analysis project focused on analyzing synthetic security logs, identifying recurring event patterns and summarizing authentication activity.

**Status:** In development

## Overview

Security logs contain records of events generated by systems and applications. Analyzing these records can help identify unusual patterns that deserve further investigation.

The goal of this project is to build a Python tool that processes example security logs, summarizes authentication events and highlights patterns such as repeated failed login attempts.

The project may later include statistical analysis and visualizations using R.

## Goals

- Learn practical Python programming.
- Understand the structure of log files and basic security events.
- Parse and summarize authentication events.
- Group failed login attempts by IP address.
- Identify configurable thresholds for repeated failures.
- Practice testing, documentation and version control with Git.
- Explore statistical analysis and visualization with R.

## Planned Features

- [ ] Read a synthetic log file.
- [ ] Parse timestamps, event types, usernames and IP addresses.
- [ ] Count successful and failed login attempts.
- [ ] Summarize failed attempts by IP address.
- [ ] Flag IP addresses that exceed a configurable threshold.
- [ ] Handle malformed or incomplete log entries.
- [ ] Add automated tests.
- [ ] Generate a clear summary report.
- [ ] Explore event frequencies and visualizations with R.

## Project Structure

The project structure will evolve as new features are implemented.

- `src/` — Python source code.
- `data/` — synthetic example data.
- `tests/` — automated tests.
- `reports/` — selected analysis outputs.
- `r_analysis/` — optional statistical analysis using R.

## Data and Privacy

This project is intended for learning and defensive analysis.

Example data should be synthetic or obtained from appropriate public sources. Do not upload confidential logs, credentials, tokens or personal information.

A flagged pattern is not proof of malicious activity. Findings require context and further investigation.
